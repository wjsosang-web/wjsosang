# 원주청년소상공인협회 공식 홈페이지

Next.js 15 (App Router) + TypeScript + Tailwind CSS 4
배포는 Vercel, 데이터베이스는 Supabase(PostgreSQL)를 사용합니다.

## 실행

```bash
npm install
npm run dev
```

http://localhost:3000

| 명령 | 설명 |
| --- | --- |
| `npm run dev` | 개발 서버 |
| `npm run build` | 프로덕션 빌드 |
| `npm run typecheck` | 타입 검사 |

## 지금까지 만든 것

시안(디자인 목업) 기준으로 5개 페이지를 모두 구현했습니다.

- **메인홈** — 히어로 슬라이드(3장 + 미리보기 카드) / 숫자로 보는 원청협 /
  공지사항+최근 활동 / 회원업장 / 예정 행사 / 협회 연간일정
- **협회소개** — 히어로 / 회장 소개 / 협회 이야기 / 조직구성 / 함께하는 사람들(탭) /
  주요사업 / 걸어온 길 / 함께하는 기관
- **회원업장** — 히어로 겹침 검색바 / 업종·지역 칩 필터 / 이달의 추천 /
  전체 목록(6열) / 플레이스 URL 간편등록 안내 / 업장 상세페이지
- **협회활동** — 탭(전체·공지사항·협회활동·행사) / 주요활동 / 활동 카드 /
  다가오는 행사 / 게시글 상세(본문 + 활동사진 + 사진별 설명)
- **협회문의** — 연락처 4종 / 문의 폼(동의 필수) / 회원가입 안내 / 오시는 길 / FAQ
- **네이버 플레이스 자동채움 API** — `POST /api/admin/place-import`
- **DB 스키마 전체** — `supabase/migrations/` (0001 기본, 0002 플레이스·프로필)

## 설계에서 지킨 것

### 1. 회원과 업장은 별개다

```
members ──< member_businesses >── businesses
```

`member_businesses` 연결 테이블 하나로 다음이 전부 표현된다.

- 회원 1명이 여러 업장 운영 (예: 이종현 → 픽폰 + 픽카)
- 업장 1곳에 공동대표 여러 명
- 회원별로 어떤 업장을 수정할 수 있는지 (`can_edit`)

회원 로그인을 켤 때 테이블을 고칠 일이 없다.

### 2. 권한과 승인 구조를 미리 넣었다

- `role_type` — `superadmin` / `admin` / `officer` / `member`
- `pending_edits` — 회원이 수정한 내용을 협회가 승인한 뒤 공개하는 대기열
- RLS 정책은 "공개된 것만 누구나 읽기"로 열어두고, 회원용 정책은 주석으로 준비만 해뒀다

### 3. 코드에 내용을 박지 않았다

숫자, 공지, 활동, 임원, 업장, 팝업, 연혁, 협력기관 전부 데이터에서 읽는다.
조직도도 이미지가 아니라 임원 데이터로 그리므로, 직책만 바꾸면 조직도가 따라 바뀐다.

페이지는 `src/lib/repo` 의 함수만 호출하고, 이 파일 내부만 Supabase 쿼리로 바꾸면
화면 코드는 손대지 않는다.

## 회원업장 검색

`src/lib/search.ts`

**검색되는 항목**

| 화면에 안내하는 것 | 안내하지 않는 것 |
| --- | --- |
| 업장명, 업종, 한 줄 소개, 상세 소개, 주소, 지역 | **대표자명**, 관리자 등록 키워드, **협회 직함**(회장·이사·감사·사무국장·재무국장 등), 소속국, **플레이스 대표키워드**, **메뉴 이름** |

- "사무국장" → 이종현 사무국장이 운영하는 픽폰·픽카
- "박승환" → 회장이 운영하는 업장
- "바스크치즈케이크" → 그 메뉴를 파는 카페
- "반곡동" → 반곡동에 있는 회원업장

직함·대표자명·메뉴로도 검색된다는 사실은 화면에 표기하지 않는다.

**노출 순서**

1. `priority` 가 지정된 업장 (관리자가 회장단·이사진 순서를 직접 정한다)
2. 나머지는 랜덤 — 단, 서버와 브라우저가 같은 순서를 만들어야 하므로
   날짜를 시드로 쓰는 결정적 셔플을 쓴다. 하루 단위로 순서가 새로 섞인다.

**노출 개수** — 모바일 3열 × 5줄 = 15곳을 먼저 보여주고, 더보기로 15곳씩 늘린다.

## 업장 사진 우선순위

`src/lib/images.ts`

```
① 회원(또는 관리자)이 올린 대표사진
② 회원이 올린 사진 중 첫 장
③ 네이버 플레이스에서 가져온 대표사진
④ 없으면 자리표시 무늬
```

회원 사진(`cover_image`)과 플레이스 사진(`place_photo`)을 **다른 칼럼**에 둔다.
그래서 회원이 나중에 자기 사진을 올리는 순간 자동으로 그쪽이 앞선다.
플레이스 사진이 쓰이는 동안에는 상세페이지에 출처를 표기한다.

임원 사진도 같은 방식이다. 조직도에 등록한 사진이 없으면 회원 본인이 올린
프로필 사진(`members.profile_image`)을 쓴다.

## 네이버 플레이스 자동채움

관리자 업장등록 화면의 [업장정보 불러오기] 버튼이 호출하는 API다.

```
POST /api/admin/place-import
{ "url": "https://naver.me/xxxxxxx" }
```

**자동으로 채워지는 것**

업장명 · 업종 · 주소 · 지역(읍면동) · 전화번호 · 영업시간 · 위치좌표 ·
대표사진 · 대표키워드 · 메뉴(이름+가격)

**직접 입력해야 하는 것**

**대표자명** · 한 줄 소개 · 협회 등록 키워드 · 업장 소개 · 홍보글
(플레이스에 없는 정보다)

**동작 방식**

네이버는 플레이스 상세정보 공개 API를 제공하지 않는다. 그래서 두 경로를 섞는다.

| 경로 | 가져오는 값 | 안정성 |
| --- | --- | --- |
| 네이버 공식 지역검색 API | 주소, 업종, 전화, 좌표 | 높음 (키 필요) |
| 플레이스 페이지 파싱 | 대표사진, 메뉴, 대표키워드, 영업시간, 좌표 | 네이버가 페이지를 바꾸면 깨질 수 있음 |

페이지 파싱은 **경로를 콕 집지 않고 데이터 모양으로 찾도록** 만들었다.
일부가 실패해도 나머지는 채워지고, 못 가져온 항목은 `missing` 으로 돌려줘서
관리자가 그 칸만 직접 채우면 된다.

**중요: 자동 등록이 아니라 자동 채우기다.** 응답은 '초안'이며 그대로 저장하지 않는다.
관리자 확인 화면을 거쳐야 한다. 잘못된 업종 분류나 오래된 정보가 그대로 공개되는 걸 막는다.

**보안** — 서버가 아무 주소나 대신 호출하면 내부망을 찔러보는 통로가 된다.
네이버 도메인만 허용하고 리다이렉트 단계마다 다시 검사한다.
관리자 로그인을 붙일 때 이 라우트에 **반드시 세션 검사를 추가해야 한다.**
(`src/app/api/admin/place-import/route.ts` 의 TODO)

**설정** — `NAVER_SEARCH_CLIENT_ID` / `NAVER_SEARCH_CLIENT_SECRET`
(https://developers.naver.com/apps 에서 "검색" API 추가)
키가 없어도 동작하지만 주소·업종 정확도가 떨어진다.

## 데이터 교체 방법

지금은 `src/lib/data/seed/*.json` 을 읽는다. 전부 예시 데이터이므로 실제 값으로 바꾸면 된다.

| 파일 | 내용 |
| --- | --- |
| `site.json` | 협회 기본정보, 숫자, 팝업, 협회 이야기, 주요사업, 연혁, 협력기관 |
| `businesses.json` | 회원업장 |
| `members.json` | 회원 + 회원-업장 소유관계 |
| `org.json` | 조직도·임원 (직함 검색과 조직도의 근거 데이터) |
| `posts.json` | 공지사항 / 활동소식 / 행사 |

사진은 전부 `null` 이라 자리표시 무늬가 나온다. 실제 이미지 경로를 넣으면 바로 표시된다.

## 배포 (GitHub → Vercel)

1. 이 저장소를 GitHub에 올린다.
2. Vercel에서 `New Project` → 이 저장소를 선택한다.
   Framework는 Next.js로 자동 인식되며 별도 빌드 설정이 필요 없다.
3. Vercel 프로젝트 설정 → Environment Variables 에 `.env.example` 의 값을 넣는다.
   Supabase 연결 전이라면 `DATA_SOURCE=seed` 만 있어도 동작한다.
4. `main` 브랜치에 push하면 자동 배포된다.

`SUPABASE_SERVICE_ROLE_KEY` 는 서버에서만 쓰는 키다.
`NEXT_PUBLIC_` 접두사를 붙이면 브라우저에 노출되므로 절대 붙이지 않는다.
